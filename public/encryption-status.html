How Encryption Works

Learn more about the encryption model

Algorithm: X25519 key exchange + XSalsa20-Poly1305 authenticated encryption (TweetNaCl nacl.box). This is a well-audited, modern scheme that provides confidentiality and authenticity.

Message flow:

  1. You and the server each generate a key pair on first use.
  2. You perform a handshake: exchange public keys. Your private key never leaves your device.
  3. Both sides independently compute the same shared secret (Diffie-Hellman). The secret is never transmitted.
  4. Each message is encrypted with a unique random nonce. The ciphertext is sent to the server.
  5. The server relays ciphertext. It cannot read your messages.
  6. The recipient decrypts locally using the shared secret and the nonce.

Replay protection: The server tracks nonces per session. A nonce already seen is rejected, preventing replay attacks.

Key export: When you export your keys, they are encrypted using PBKDF2 (310,000 iterations, SHA-256) → AES-GCM with your chosen password before download. The raw private key is never written to disk unencrypted.

Trust assumptions: This model protects message contents from the server and from network observers. It does not protect against a compromised browser extension, a compromised device, or a server that has been modified to return a malicious public key (key-substitution attack). For the highest security, verify the server's public key out-of-band.
